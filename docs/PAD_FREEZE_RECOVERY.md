# PAD出撃時の暗転・停止への対策

ユーザーから「PADでプレイすると暗転・停止し、設定は開ける」と報告。標準配置の仮想PADによるPCのタイトル→初回ガイド→全6機体の戦闘は動作したため、報告環境の正確な発生原因は未確定。物理PADは未確認。

調査で、PAD処理を含むRAF内の例外が次フレームの予約前に発生すると、その後のゲーム描画と進行が永久停止する構造を確認した。DOMの設定ボタンは独立して動作する。

対策:
- 次フレームを処理開始時に予約し、入力・戦闘・音楽・描画の異常で予約が失われないようにする。例外発生時は戦闘を一時停止し、操作と描画の復帰を可能にする。
- ブラウザが管理するPADのボタンと軸は一度コピーして読む。Array.mapの存在を前提にせず、配列状の値・型付き配列・欠けた値を扱う。読み取り途中の例外はPAD入力の境界で捕捉して入力を解除する。
- 実際に処理エラーが出た時だけ通知を表示し、設定の負荷ログJSONに処理段階・エラー・スタック・回数を追加する。履歴は最大8件。生のPAD識別情報や入力履歴は保存しない。
- オフラインキャッシュをpc-pad-recovery-v2へ更新。

検証は既存6シナリオに加え、実出撃経路、配列状の機器入力、機器読取例外から設定を開いて再開、描画例外後のPAD再開を実ブラウザで行う。出撃経路は初回ガイド・再出撃を含め全6機体を通し、HUD時刻の進行を確認する。戦闘の途中で自然にレベルアップ画面へ移ることはフリーズと区別し、この開始確認では自動保留を設定する。
