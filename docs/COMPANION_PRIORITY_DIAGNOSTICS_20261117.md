# 標的優先斬撃と被弾診断（2026-11-17）

基点はmain 12f26bb（PR #89）。前回の全6機体比較では、通常のDOGが4/20、PHANTOMが6/20と他機体より低かったため、原因の確認と不具合修正を続ける。

## 選択した標的への斬撃

ファントムの索敵はレリック敵や迎撃対象を選ぶが、斬撃の命中処理は空間索引の候補順に巻き込み上限を消費していた。密集した敵が先に3体命中すると、正面の標的には当たらないケースがある。

現在選択中の標的が候補に含まれる場合は最初に判定し、残りは元の候補順を使用する。命中済みSetで二重命中を防ぐ。射程・扇角・壁・無敵・巻き込み数・威力は従来どおり。NOVAと標的を持たない残響は既存の順序を維持し、候補配列自体は変更しない。

## 被弾原因の記録

既存の開発用計測を開始したときだけ、接触・敵弾・PHASE弾・範囲攻撃別に被弾数とHP損失を集計する。シールドで吸収した分をHP損失へ加算しない。直近64件に時刻、被弾前HP、吸収後シールド、位置、敵数とボスを記録する。詳細を切り詰めても全期間の集計は保持する。レポートはコピーを返す。通常プレイで記録を開始しない限り、履歴は作らない。

全機体の既存通しCIにもARSENAL_INCOMINGログを追加する。旧基準版にはこの計測項目がないためnullとして扱い、従来のクリア比較を維持する。

## ローカルAI実行の時刻

Node VMの検証用ホストは従来drive(dt)を直接呼んでいた。一方、ブラウザの通し比較はadvanceSimulation(dt)で戦闘時刻と演出・周期武装の位相を一緒に進める。VM側も同じ固定ステップを使用し、各試行開始時に位相をリセットする。前回の公開クリア率表はブラウザ版のため、この修正で過去の表を置き換えない。VMの結果をFPSや描画性能の証拠にはしない。

## 検証

密集した敵群の末尾に標的があるケースをレリック・大ボス・通常敵で検証し、先頭命中・上限維持・二重命中なし・候補順の保持を確認する。実際の接触、PHASE弾、地雷の被弾経路、無敵、履歴の上限と集計、レポートコピー、VM時計の更新と試行間リセットを検証する。

通常30分・チャレンジ15分を各機体20シード（17〜36）、同じAIで基準版と調整版を比較する。死亡と時間切れを分母に含め、最終ボス撃破のみクリアとする。PC/スマホ・最大ファントム/ダーツ・複合レイド・2倍速・セーブ/PWAの回帰も確認し、CI合格後に統合する。
